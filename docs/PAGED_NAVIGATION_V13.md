# 라니팡 v1.3 — 게임형 페이지 전환 UI

## 구현 기준
- 사용자가 직접 이동할 콘텐츠는 브라우저 스크롤바 대신 게임형 이전/다음 화살표를 우선한다.
- 현재 페이지, 전후 이동 가능 여부, 접근 가능한 전체 레벨을 명확히 제공한다.
- 페이지 전환은 UI만 바꾼다. 퍼즐 진행 상태/저장 키/레벨 조건 변경 금지.
- `prefers-reduced-motion`, 키보드 방향키, 키보드 포커스, 모바일 안전 영역을 지원한다.

## 월드맵
- 지도 1개 지역 25단계의 노드를 화면 높이에 따라 3 / 6 / 9 / 12개씩 분할.
- 세로 스크롤은 없고 `#lany-map-prev`, `#lany-map-next` 버튼으로 페이지 이동.
- 페이지별 노드의 경로선 SVG를 독립적으로 새로 계산하고, 이전 요청의 RAF는 렌더 토큰으로 무효화.
- 10개 지역 탭은 너비에 따라 3 / 4 / 5개씩 표시. 지역 이전/다음 버튼 제공.
- 보유 별, 열림 여부, 이동 중인 스테이지, 스테이지 ID, 완료 상태는 기존 그대로 사용.
- 첫 페이지/끝 페이지에서 버튼 비활성화, 방향키로 전후 페이지 탐색.

## 동물 친구 도감
- 전체 30종을 높이에 따라 6 / 9 / 12종씩 렌더.
- 새 페이지를 열 때에만 그림 카드를 생성하고 `loading=lazy` 이미지 사용.
- 마지막 페이지까지 이동 시 총 30종 모두 탐색 가능. 이전/다음 버튼 비활성화 처리.

## 보조 화면
- 게임 방법: 2페이지, 페이지 번호 및 명확한 닫기 버튼.
- 단계 준비: 낮은 높이(740px 미만)에서 목표/기록과 시간/도움 아이템으로 2페이지 분할. 실행·지도 복귀 버튼은 공통 고정. 큰 화면에서는 한 화면에 양쪽 내용을 함께 배치.
- 시험용 난이도 선택: 한 페이지당 2개 메뉴. 현재 시험용 설정이 실제 250단계 난이도에는 적용되지 않는다는 경고 명시.
- 단계 편집기: 8x8 작업 보드와 설정·공유 페이지 분리. 기존 inline 클릭 핸들러의 스코프 오류를 고치고 실제 클릭 리스너 연결.
- 안전을 위해 길이가 유동적인 일부 대전/추가 기능 창에는 짧은 화면의 스크롤 폴백을 남김. 화면을 강제로 잘라 사용 불가능하게 만들지 않음.

## 검증
- `tools/check-pages-v13.cjs`: 250/10/30 숫자 보존, 페이지 분배 검증, 소스 문법 검사, 한글 UI, 오프라인 캐시, 모션 감소.
- `tests/verify-paging-v13.py`: 실제 Chromium에서 320×568 모바일, 390×844 모바일, 1366×768 PC, 페이지 버튼, 세계/지도, 준비창, 도감 30종, 튜토리얼, 시험용 난이도, 단계 편집기, 스테이지 상태 보존 검증.
- GitHub Actions `browser-pages`: 3뷰포트 스크린샷 6장 업로드 및 사용 가능한 화면 높이/너비 검증.
- 기존 `tests/verify-world-map.py`, `tests/verify-map-touch.py`, `tests/verify-friends-mobile.py`는 새로운 페이지 규칙으로 업데이트.
- 본 검증은 Chromium 환경 대상이며 실제 삼성 인터넷/iOS Safari 단말별 동작 검증은 별도 필요.

## 배포
- GitHub Pages는 `main` 푸시 이후 품질검사를 통과해야 게시.
- Firebase 정식 live는 `ops/firebase-live-release.json` 릴리스 승인 설정이 갱신될 때 별도로 배포.
- 소셜 로그인, Firestore, Storage 등 Firebase 사용자 데이터는 변경 대상이 아님.
