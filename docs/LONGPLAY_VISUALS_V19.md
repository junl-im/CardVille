# 라니팡 v1.9 — 장시간 매치 플레이 안정화 + WebP 결과 팝업

## v1.8에서 추가 발견한 실제 비용
- 기존 `animPart` 파티클은 게임 화면에서 실제 그리기만 생략하고 **requestAnimationFrame 콜백은 계속 예약**하고 있었음.
- 기존 `LanyPolish.down()`은 퍼즐 블록을 누를 때마다 작은 WebP를 `wink`으로 바꿨다가 복원하여 스와이프마다 이미지 디코딩/재할당 가능성이 있었음.
- 퍼즐 셀 재사용 이후 `LanyPolish.face()`가 `src`를 임시 표정으로 바꾼 다음 다음 단계 렌더에서 이미지의 `data-gem`만 검사하여 **임시 표정 이미지가 그대로 남을 위험**이 있었음.

## v1.9 실제 수정
1. 첫 화면 파티클 `requestAnimationFrame`을 타이틀에서만 실행. 게임 진입/탭 숨김에서는 완전 cancel. 돌아오면 20FPS 상한으로 재시작.
2. 타일 누름은 `transform`만 사용하여 표정 WebP를 매 터치마다 교체하지 않음. 실제 매치 시 최대 2개(모바일)/4개(PC)만 특수 표정으로 전환. 다음 렌더는 반드시 원본 동물 이미지로 복귀.
3. 결과 팝업: 기존 제작 `rabbit-cheer.webp`, `bear-surprise.webp`, **검은 고양이 `cat-cheer.webp`**, `chick-wink.webp`를 함께 사용. 모바일에 맞는 별 획득 애니메이션과 점수 명확화. 효과는 CSS transform/opacity 중심, 필수 텍스트·버튼은 실제 HTML 유지.
4. 선택적 성능 진단: **주소에 `?perf=1`** 를 추가하면 화면 오른쪽 위에 FPS, 프레임 지연 p95, 최대 지연, Long Tasks, JS 힙(지원 브라우저), 보드 셀, 이펙트 DOM 개수, 보드 렌더 수, 단계 시작 수 표시. 평상시 실행하지 않음. 개인정보·진행 정보·성능 수치를 **외부로 전송하거나 로컬 저장하지 않음.** X 버튼으로 즉시 완전 해제.
5. SW 오프라인 프리캐시에 `lany-raster-v18.css` 누락되어 있던 점도 함께 수정하고 v1.9 버전으로 갱신.
6. 250개 스테이지·잠금·보상·진행 데이터, WebP 캐릭터(검은 고양이), PWA 설치 유지.

## 테스트
- `tools/check-longplay-v19.cjs`: 게임 플레이 중 rAF 종료, 복구 가능한 마스코트 스프라이트, 초경량 결과 이미지, 로컬 전용 성능 측정, PWA 캐시 검사.
- `tests/verify-longplay-v19.py`: 390×844, 320×568, 1366×768에서 **9라운드×2회 실제 성공 매치**를 시도하여 스와프→해소→중력→결과 루프 수행. 64개 보드 DOM 재사용, VFX 정리, 점수 증가, 원본 이미지 복구, 승리·실패 이미지 및 FPS 진단 쿼리 동작 검증. 기존 40회 연속 초기화 테스트도 유지.
- 검증 기준은 PC 에뮬레이터의 모바일 뷰포트. **실제 기종 GPU·열·메모리 사용량을 확인한 결과가 아님.** 진단 링크를 실기기에서 열어 10~20분 플레이하면 스크린샷으로 프레임/메모리 추이를 비교할 수 있음.

## 실제 단말기 검사 방법
- 정식 사이트: `https://cardville.web.app/?v=1.9.0&perf=1`
- 미리보기 사이트: `https://cardville--cardville-match3-preview-ikhmalki.web.app/?v=1.9.0&perf=1`
- 게임 시작 전과 5판/10판/15판 뒤의 FPS, p95, Long Tasks, 보드/효과 노드 수와 힙(지원 시)을 비교. 모바일 브라우저는 성능 측정 가능 항목이 기종/브라우저마다 다름.
- 진단을 종료하려면 화면 오른쪽 위 X 또는 주소에서 `perf=1` 제거. 기록 데이터의 삭제나 재설정은 불필요.
